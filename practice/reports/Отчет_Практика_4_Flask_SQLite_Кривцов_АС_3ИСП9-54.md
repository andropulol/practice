## Цель работы

Научиться передавать данные из базы SQLite в HTML-шаблон Jinja2
и выводить их списком на странице.

## Структура проекта

```
python/04_flask_read/
├── main.py
├── templates/
│   └── tasks.html
└── app.db          # создаётся автоматически
```

При первом запуске приложение само создаёт таблицу и добавляет три
демонстрационные записи, поэтому проект можно запускать отдельно.

## Ход выполнения

1. Создан шаблон `templates/tasks.html` с циклом
   `{% for task in tasks %}` и условием `{% if tasks %}`.
2. В `main.py` добавлена функция `connect_db()`, которая устанавливает
   `conn.row_factory = sqlite3.Row` — доступ к колонкам по имени.
3. Функция `select_tasks()` выполняет `SELECT id, title, status`
   и закрывает соединение в `finally`.
4. Результат передаётся в шаблон: `render_template("tasks.html", tasks=...)`.
5. Статус выводится бейджем: «в работе» / «выполнена», выполненные задачи
   зачёркнуты через CSS-класс `is-done`.

## Результаты запуска

```text
GET / -> 200
В таблице отображаются записи:
  ID 1  Сверить показания счётчиков   выполнена
  ID 2  Записаться на консультацию     в работе
  ID 3  Проверить домашнее задание     в работе
```

Проверка «живой» связи: запись, добавленная в базу из другого скрипта,
появляется на странице после обновления — Flask читает тот же файл `app.db`.

**Скриншот 1.** Страница со списком задач.
**Скриншот 2.** Зачёркнутая выполненная задача.
**Скриншот 3.** Пустая база: сообщение «В базе пока нет задач».

## Ответы на контрольные вопросы

**1. Зачем нужен шаблонизатор Jinja2, если можно вернуть HTML-строку?**
Jinja2 разделяет Python-код и разметку, позволяет переиспользовать шаблоны,
автоматически экранирует данные (защита от XSS) и делает код читаемым.
Собирать HTML конкатенацией строк неудобно и опасно.

**2. Чем `{{ ... }}` отличается от `{% ... %}`?**
`{{ ... }}` выводит значение выражения в HTML. `{% ... %}` — управляющая
конструкция: цикл, условие, наследование, комментарии.

**3. Что делает `render_template('tasks.html', tasks=rows)`?**
Находит файл `templates/tasks.html`, прогоняет его через Jinja2,
подставляет переданные переменные (в шаблоне появляется `tasks`)
и возвращает готовую HTML-строку.

**4. Почему при чтении данных не нужен `conn.commit()`?**
`SELECT` не изменяет базу. Фиксировать нечего, поэтому достаточно
прочитать строки и закрыть соединение.

**5. Что такое `sqlite3.Row` и почему `task.title` работает только с ним?**
Это обёртка над строкой результата, которая поддерживает доступ по имени
колонки. Обычный кортеж знает только индексы, поэтому у него нет атрибута
`title`.

**6. Куда Flask кладёт файлы шаблонов по умолчанию и можно ли это изменить?**
В папку `templates` рядом с модулем приложения. Можно изменить через
`Flask(__name__, template_folder='путь')`.

**7. Что выведет шаблон, если `items`/`tasks` — пустой список?**
Сработает ветка `{% else %}` и появится сообщение о том, что список пуст.

## Вывод

Данные из SQLite выводятся в HTML через Jinja2. `sqlite3.Row` делает шаблон
читаемым, а соединение закрывается сразу после выборки.
