## Часть B. Практические задания (20 баллов)

### Задание 11. Анализ кода (5 баллов)

Исходный фрагмент:

```python
import sqlite3

def add_task(title):
    conn = sqlite3.connect('app.db')
    cursor = conn.cursor()
    cursor.execute("INSERT INTO tasks (title) VALUES (?)", title)
    return True
```

**Ошибка 1. Параметр передан не в кортеже.**
`execute()` ожидает последовательность значений. Строка `title` формально
тоже является последовательностью, поэтому SQLite воспринимает её
как набор отдельных параметров и выдаёт
`ProgrammingError: Incorrect number of bindings supplied`
(для строки из одного символа ошибки не будет — это случайное совпадение).
**Исправление:** передать кортеж из одного элемента — `(title,)`.

**Ошибка 2. Нет `conn.commit()`.**
Изменения остаются в незавершённой транзакции и отменяются при закрытии
соединения. В файл `app.db` запись не попадает.
**Исправление:** вызвать `conn.commit()` после `execute()`.

**Ошибка 3. Нет `conn.close()`.**
Соединение остаётся открытым, файл базы блокируется, возможна ошибка
`database is locked`. Кроме того, функция всегда возвращает `True`,
даже если вставка не удалась.
**Исправление:** закрывать соединение в `finally`, а `True` возвращать
только после успешного `commit()`.

Дополнительно: отсутствует `try/except` с `rollback()`, поэтому при сбое
транзакция останется незавершённой.

Исправленный вариант:

```python
import sqlite3

def add_task(title):
    conn = sqlite3.connect('app.db')
    try:
        conn.execute("INSERT INTO tasks (title) VALUES (?)", (title,))
        conn.commit()
        return True
    except sqlite3.Error as err:
        conn.rollback()
        print(f"Не удалось добавить задачу: {err}")
        return False
    finally:
        conn.close()
```

Проверка запуском (`task11_fixed.py`):

```text
add_task('Проверка') -> True
add_task('Ещё одна') -> True
Содержимое таблицы: [(1, 'Проверка'), (2, 'Ещё одна')]
Строк в базе: 2
```

### Задание 12. Дописать код (7 баллов)

```python
import sqlite3

def delete_task_by_id(task_id):
    conn = sqlite3.connect('app.db')
    try:
        cursor = conn.execute("DELETE FROM tasks WHERE id = ?", (task_id,))
        conn.commit()
        return cursor.rowcount
    except sqlite3.Error as err:
        conn.rollback()
        print(f"[delete_task_by_id] ошибка: {err}")
        return 0
    finally:
        conn.close()
```

Соответствие критериям:

| Критерий | Реализация |
|---|---|
| Открытие соединения | `sqlite3.connect('app.db')` |
| Параметризованный DELETE | `WHERE id = ?`, значение `(task_id,)` |
| Фиксация изменений | `conn.commit()` после `execute` |
| `try/except/finally` | все операции в `try`, закрытие в `finally` |
| `rollback` и возврат `0` | `conn.rollback()` и `return 0` в `except` |
| Число удалённых строк | `return cursor.rowcount` |

### Задание 13. Мини-сценарий (8 баллов)

Что происходит после нажатия кнопки «Добавить», если форма отправляется
на `/` методом POST:

1. **Браузер.** Собирает значение поля `name="title"`, формирует
   POST-запрос на `/`, помещает данные в тело запроса и отправляет их
   на сервер.
2. **Flask.** Сопоставляет URL с маршрутом `/`, проверяет, что метод POST
   разрешён, и вызывает функцию-обработчик `index()`.
3. **Чтение и валидация.** Обработчик проверяет `request.method == 'POST'`,
   читает `title = request.form.get('title', '').strip()` и отбрасывает
   пустую или слишком длинную строку, возвращая форму с сообщением
   об ошибке.
4. **Открытие соединения.** Выполняется `sqlite3.connect('app.db')`,
   создаётся курсор.
5. **INSERT.** Выполняется параметризованный запрос
   `INSERT INTO tasks (title) VALUES (?)` с кортежем `(title,)` —
   это защищает от SQL-инъекции.
6. **Фиксация или откат.** При успехе вызывается `conn.commit()`,
   и данные записываются на диск. При исключении — `conn.rollback()`,
   и изменения отменяются.
7. **Закрытие и редирект.** В `finally` вызывается `conn.close()`,
   после чего сервер отвечает `302` и `redirect(url_for('index'))`.
   Браузер выполняет GET `/`.
8. **Результат.** Обработчик GET делает `SELECT`, передаёт строки
   в шаблон Jinja2, и пользователь видит обновлённый список, где уже есть
   новая задача. Повторное обновление страницы (F5) не создаёт дубликат,
   потому что повторяется GET, а не POST.
