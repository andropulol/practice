## Цель работы

Отработать полный цикл добавления записи: форма → POST-запрос → INSERT →
`commit` → редирект на главную страницу.

## Структура проекта

```
python/05_flask_create/
├── main.py
├── templates/
│   └── tasks.html
└── app.db
```

## Ход выполнения

1. В шаблон добавлена форма:
   `<form method="POST" action="{{ url_for('home') }}">` с полем `name="title"`.
2. Маршрут объявлен с двумя методами: `@app.route("/", methods=["GET", "POST"])`.
3. На POST данные читаются через `request.form.get("title", "").strip()`.
4. Выполняется серверная валидация: пустая строка и длина больше 200 символов
   отклоняются с сообщением об ошибке.
5. `INSERT` выполняется параметризованно, затем `commit()` и `close()`.
6. После успешной вставки — `redirect(url_for("home"))` (паттерн PRG).

## Ответы на контрольные вопросы

**1. Чем POST принципиально отличается от GET и почему формы отправляют именно POST?**
GET передаёт данные в URL и предназначен для чтения, его можно кэшировать
и повторять. POST передаёт данные в теле запроса и не должен кэшироваться.
Форма создаёт или изменяет запись, поэтому используется POST.

**2. Что произойдёт, если убрать `methods=['GET', 'POST']`?**
Маршрут будет принимать только GET. При отправке формы сервер вернёт
`405 Method Not Allowed`, и добавление не сработает.

**3. Зачем нужен паттерн Post/Redirect/Get? Что сломается без него?**
После POST сервер отвечает редиректом на GET-страницу. Без этого обновление
страницы (F5) повторит POST и создаст дубликат записи. PRG разрывает эту цепочку.

**4. Почему `url_for('index')` лучше, чем жёсткая строка `'/'`?**
`url_for` строит адрес по имени функции. Если маршрут изменится, ссылки
обновятся автоматически. Жёсткая строка сломается.

**5. Почему `request.form.get('title', '')` безопаснее, чем `request.form['title']`?**
Если поля нет в запросе, обращение по ключу выбросит `KeyError` и вернёт
ошибку 400. `get()` вернёт значение по умолчанию, и код обработает ситуацию
спокойно.

**6. Зачем серверная валидация, если в HTML уже есть `required`?**
`required` проверяет только браузер. Запрос можно отправить в обход формы
(curl, Postman, DevTools), поэтому сервер обязан проверять данные сам.

**7. В каком порядке идут транзакции при добавлении задачи через форму?**
Открытие соединения → `INSERT` с параметром → `commit()` → `close()` →
`redirect` → браузер делает GET → `SELECT` → рендер шаблона.
