## Задание 11. Анализ кода (5 баллов)

Исходный фрагмент:

```python
import sqlite3

def add_task(title):
    conn = sqlite3.connect('app.db')
    cursor = conn.cursor()
    cursor.execute("INSERT INTO tasks (title) VALUES (?)", title)
    return True
```

**Ошибка 1. Параметр передан не в кортеже.**
`execute()` ожидает последовательность значений. Строка `title` тоже является
последовательностью, но SQLite воспримет её как набор символов и выдаст
`ProgrammingError: Incorrect number of bindings supplied`.
Исправление: `(title,)` — кортеж из одного элемента.

**Ошибка 2. Нет `conn.commit()`.**
Запись останется в памяти и будет отменена при закрытии соединения.
Данные не попадут в файл `app.db`.
Исправление: вызвать `conn.commit()` после `execute()`.

**Ошибка 3. Нет `conn.close()`.**
Соединение остаётся открытым, файл базы блокируется, возможна ошибка
`database is locked`. Кроме того, функция всегда возвращает `True`,
даже если запись не удалась.
Исправление: закрывать соединение в `finally`, а результат возвращать
только после успешного `commit()`.

Дополнительно: отсутствует `try/except` с `rollback()`, поэтому при сбое
транзакция останется незавершённой.

Готовый исправленный вариант: [`task11_fixed.py`](task11_fixed.py).

## Задание 12. Дописать код (7 баллов)

```python
import sqlite3

def delete_task_by_id(task_id):
    conn = sqlite3.connect('app.db')
    try:
        cursor = conn.execute("DELETE FROM tasks WHERE id = ?", (task_id,))
        conn.commit()
        return cursor.rowcount
    except sqlite3.Error as e:
        conn.rollback()
        print(f"[delete] {e}")
        return 0
    finally:
        conn.close()
```

Что закрыто по критериям:

| Критерий | Реализация |
|---|---|
| открытие соединения | `sqlite3.connect('app.db')` |
| параметризованный DELETE | `WHERE id = ?`, значение `(task_id,)` |
| commit | `conn.commit()` после `execute` |
| try/except/finally | все операции в `try`, закрытие в `finally` |
| rollback + возврат | `conn.rollback()` и `return 0` в `except` |
| число удалённых строк | `return cursor.rowcount` |

## Задание 13. Мини-сценарий (8 баллов)

Что происходит после нажатия кнопки «Добавить» (форма отправляется на `/` методом POST):

1. **Браузер.** Собирает данные формы (`name="title"`), формирует POST-запрос
   на `/`, кладёт значение в тело запроса и отправляет его на сервер.
2. **Flask.** Находит маршрут `/`, проверяет, что метод POST разрешён,
   и вызывает функцию-обработчик `index()`.
3. **Проверка метода и данных.** `request.method == 'POST'` истинно,
   обработчик читает `title = request.form.get('title', '').strip()`.
4. **Серверная валидация.** Если строка пустая или слишком длинная —
   возвращается тот же шаблон с сообщением об ошибке, запись не создаётся.
5. **Открытие соединения.** `sqlite3.connect('app.db')` создаёт соединение,
   затем создаётся курсор.
6. **INSERT.** Выполняется параметризованный запрос
   `INSERT INTO tasks (title) VALUES (?)` с кортежем `(title,)` —
   защита от SQL-инъекции.
7. **Фиксация или откат.** При успехе — `conn.commit()`, данные записываются
   на диск. При исключении — `conn.rollback()`, изменения отменяются.
8. **Закрытие.** В блоке `finally` вызывается `conn.close()`, файл базы
   освобождается.
9. **Редирект (PRG).** Сервер отвечает `302` и `redirect(url_for('index'))`.
   Браузер делает GET `/`.
10. **Результат для пользователя.** Обработчик GET выполняет `SELECT`,
    передаёт строки в шаблон Jinja2, и пользователь видит список,
    в котором уже есть новая задача. Обновление страницы (F5) не создаёт
    дубликат, потому что повторяется GET, а не POST.
